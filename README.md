# 声之轨

一个原生 macOS 菜单栏音量工具。调节系统总音量，展开控制各个应用的音量，并把不同应用的声音送到指定的扬声器或耳机。

目前处于本地原型阶段，使用 SwiftUI、Core Audio Process Taps 和 AVAudioEngine 构建，不依赖第三方音频驱动或外部包。

## 功能

- **系统声音**：切换系统输出设备、调节当前设备总音量。
- **应用音量**：展开列表，为每个应用开启独立音量、静音和输出设备控制。
- **独立输出**：指定某个应用使用耳机或扬声器，也可以跟随系统输出。
- **快速切换**：切换输出时复用采集通道，音频操作在后台执行。
- **通话音量保护**：对受控应用尝试恢复播放端的压低系数；不修改系统总音量，不进行额外数字放大。
- **设置记忆**：保存应用音量、静音、输出选择和列表展开状态。
- **恢复原路径**：关闭应用控制、点击“恢复所有应用”或退出，即可解除接管。指定设备断开时停止该应用的接管并提示。

这是独立的菜单栏应用，无法在苹果自带的“声音”面板中插入应用音量滑块。

## 系统要求

- macOS 14.2 或更新版本。
- 构建需要 Swift 6 工具链（例如 Xcode 16 或更新版本）。
- 当前主要在 Apple Silicon、macOS 26.4 上验证，其他系统和设备组合仍需测试。

## 构建和运行

克隆仓库后，在项目目录运行：

```sh
zsh Scripts/build-app.sh
open dist/声之轨.app
```

也可以用 Xcode 打开 `Package.swift` 查看和编辑代码。需要使用音频权限或进行实际播放测试时，请运行打包后的 `.app`。

构建产物在 `dist/声之轨.app`。脚本使用本机临时签名，尚未配置 Developer ID 或公证，不属于正式分发版本。更新后 macOS 可能要求重新授权。

## 使用

1. 点击菜单栏中的扬声器图标，打开“声之轨”。
2. 在“系统输出”中选择设备，使用滑块调节系统总音量。部分显示器或外接设备需要在设备本身调节总音量。
3. 展开“应用音量”，打开目标应用右侧的开关。
4. 首次开启音频控制时，在 macOS 系统提示中允许音频录制；随后调整应用音量、静音或“输出到”。
5. 关闭窗口只会收起面板；通过面板中的“退出”关闭应用。

每次启动需手动开启应用控制。耳机需要先连接到 Mac，才会出现在输出列表中。

右侧开关控制的是是否接管音频，并非静音：蓝色且标注“已开启”时，应用音量与输出选择才生效；灰色“已关闭”使用系统原路径。状态文案只表示通道生命周期，不随音频内容的静音片段切换。

## 权限和隐私

打开应用、查看设备或切换系统输出不需要系统音频录制权限；接管应用音频时才会触发系统授权。

音频只在本机内存中处理，不保存音频文件、不上传、不采集屏幕图像或麦克风。音频录制权限用于取得指定应用的输出，再调整音量和播放设备。

如果曾拒绝授权，可到“系统设置 → 隐私与安全性 → 屏幕与系统音频录制”中检查本应用；名称随 macOS 版本可能不同。

## 验证

```sh
swift test
dist/声之轨.app/Contents/MacOS/SoundChannels --diagnose
```

自动测试覆盖立体声增益与静音、采样率转换、无数据时静音、缓冲满载与恢复。`--diagnose` 仅列出音频应用和设备，不启动音频接管；输出可能含有本机应用名称和设备标识，分享前请自行检查。

已在开发机验证系统总音量读写、Chrome 实时音频接管、独立输出切换、微信与 Chrome 同时建立通道，以及列表展开与收起。实际听感、延迟和音量变化仍需配合设备测试。

## 已知限制

- 通话音量保护使用系统未公开的设备 `duck` 属性，当前仅在属性可写且数据布局符合预期时启用。它是兼容处理，不保证未来 macOS 或所有设备有效；不支持的设备保持原状。
- 在开发机微信使用麦克风期间，已观察到其他音频的压低系数为 0.177828（约 −15 dB）；修复后系统日志确认声之轨播放客户端的系数为 1.0。该验证不等于所有通话软件与硬件上的听感验证。
- 只保护开启了音频控制并由声之轨播放的应用；未开启控制的应用仍走系统原路径。
- 无法仅靠应用音量控制消除蓝牙耳机启用麦克风后进入通话模式造成的音质变化。
- 蓝牙耳机切换、不同采样率的硬件切换、长时间播放、受保护媒体、睡眠唤醒和浏览器子进程归属仍需扩大兼容性测试。
- 使用基础线性重采样；输出切换仍会受到硬件和系统重新启动播放的耗时影响。
