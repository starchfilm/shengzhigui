# 声之轨

**在 Mac 上，分别控制每个应用的音量和播放设备。**

声之轨是一款原生菜单栏声音工具：调节系统总音量，展开后独立调节微信、浏览器、音乐播放器等应用的音量，并选择让声音从扬声器、耳机或其他输出设备播放。

它最初为“微信通话时，其他视频和音乐被自动压低”的场景而开发。目前是早期原型，主要在 Apple Silicon、macOS 26.4 上验证。

第一次了解这个项目，可以先看 **[产品介绍与使用场景](docs/INTRODUCTION.md)**。

## 能做什么

| 功能 | 说明 |
| --- | --- |
| 系统总音量 | 调节当前输出设备音量，切换扬声器、耳机等设备 |
| 应用独立音量 | 分别调节各个应用的音量，支持单独静音 |
| 应用独立输出 | 为应用指定播放设备，或选择跟随系统输出 |
| 通话音量保护 | 尝试让受控应用在通话期间保持原有音量 |
| 设置记忆 | 保存应用音量、静音、输出选择和列表展开状态 |
| 恢复原路径 | 关闭控制开关或退出，解除音频接管 |

声之轨使用自己的菜单栏面板，不会在苹果自带的“声音”面板中插入滑块，也不安装第三方虚拟音频驱动。

## 下载与安装

前往 **[GitHub Releases 下载 DMG](https://github.com/starchfilm/shengzhigui/releases)**。打开磁盘映像，将“声之轨.app”拖到 **Applications**，然后从“应用程序”启动。

安装包包含 Apple Silicon 和 Intel 两种架构，要求 macOS 14.2 或更新版本。当前是**临时签名、未经 Apple 公证的公开测试版**，不是正式签名发行版；macOS 可能阻止首次打开，请参考 [苹果的应用打开说明](https://support.apple.com/102445)。Intel 版本尚未实机验证。

Release 同时提供 SHA-256 校验文件。下载 DMG 与对应 `.sha256` 文件后，在下载目录运行：

```sh
shasum -a 256 -c ShengZhiGui-0.1.2-universal.dmg.sha256
```

## 构建与运行

需要 macOS 14.2 或更新版本，以及 Swift 6 工具链（例如 Xcode 16 或更新版本）。运行：

```sh
git clone https://github.com/starchfilm/shengzhigui.git
cd shengzhigui
zsh Scripts/build-app.sh
open dist/声之轨.app
```

构建脚本会生成本机临时签名的应用，位置为 `dist/声之轨.app`。也可以用 Xcode 打开 `Package.swift` 编辑源码；实际音频测试请运行打包后的 `.app`。

生成与 Release 相同结构的通用 DMG：

```sh
zsh Scripts/package-dmg.sh
```

产物在 `dist/`，包含 DMG 和 SHA-256 校验文件。发布流程监听 `v*` 标签，检查版本、运行测试并构建通用安装包后，发布为 GitHub 预发布版本。

## 三步开始使用

1. 点击菜单栏的扬声器图标，展开“应用音量”。
2. 打开目标应用右侧的开关；首次使用时，按 macOS 提示允许系统音频录制。
3. 调节该应用的音量、静音按钮或“输出到”。

蓝色开关表示接管该应用音频，灰色表示使用系统原路径，**开关本身不是静音按钮**。应用和设备列表自动更新；耳机需要先连接，才会出现在输出选项里。

应用只驻留顶部菜单栏，不显示 Dock 图标，也不会在启动时打开独立窗口。点击菜单栏图标展开面板，点击面板外收起；点击“退出”关闭应用。每次启动需手动开启应用控制，之前设置的音量和输出选择会保留。更多操作见 [完整介绍](docs/INTRODUCTION.md)。

## 通话音量保护：请先了解范围

- **只保护开启了音频控制的应用。** 想让 Chrome 视频不被压低，就需要打开 Chrome 的控制开关，仅打开微信不够。
- 开发机已验证微信通话场景，并得到视频音量恢复正常的听感反馈；不代表所有通话软件、系统和设备均兼容。
- 保护功能使用系统未公开的设备属性；不支持的设备保持原状，后续系统更新仍需验证。
- 蓝牙耳机启用麦克风后进入通话模式导致的音质降低，是另一类问题，不能仅靠音量控制消除。

## 隐私与权限

音频只在本机内存中处理，不保存音频文件、不上传声音、不采集麦克风或屏幕图像。系统音频录制权限用于取得目标应用输出，再调节音量和播放设备。

打开面板、查看设备和切换系统输出不需要音频录制授权；首次开启应用控制时才会触发系统提示。如果曾拒绝，可以在“系统设置 → 隐私与安全性 → 屏幕与系统音频录制”中检查，具体名称随 macOS 版本可能不同。

## 已验证与待验证

已验证系统音量读写、应用独立输出、微信与 Chrome 同时控制、通话音量保护，以及关闭控制和退出后的系统设置恢复。8 项自动测试覆盖增益、静音、缓冲恢复、高频幅度、采样率转换、声道隔离、抗混叠和稳态样本误差。

开启控制后会经过缓冲和音频处理，**不是完全无损直通，也不是零延迟**。蓝牙耳机、不同采样率硬件切换、长时间播放、受保护媒体、睡眠唤醒和浏览器子进程归属仍需扩大测试。内部信号指标不能替代对实际扬声器或耳机的测量，详细结果见 [音频验证记录](docs/AUDIO_VALIDATION.md)。

## 开发与问题反馈

采用 SwiftUI、Core Audio Process Taps、AVAudioEngine 和 C 音频桥，不依赖外部包。

```sh
swift test
dist/声之轨.app/Contents/MacOS/SoundChannels --diagnose
```

`--diagnose` 只列出本机音频应用和设备，不启动接管。诊断结果可能包含应用名称和设备标识，分享前请检查。

反馈问题时，请提供 macOS 版本、Mac 芯片、音频设备类型、相关应用，以及复现步骤。优先使用不含个人通话内容的测试场景；不需要提供通话录音。
