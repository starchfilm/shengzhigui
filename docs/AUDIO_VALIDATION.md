# 音频验证记录

日期：2026-11-01。开发机为 Apple Silicon Mac，macOS 26.4。

## 结论

声之轨启用应用控制后会改变音频路径，不能承诺完全无损或零延迟。此次检查发现并修正了旧版的高频衰减问题。修复后内部合成信号测试通过；关闭控制和退出应用时，已核对系统输入、输出设备的持久 UID、采样率、总音量与静音状态保持不变。

## 发现与修复

旧版缓冲补偿使用固定的 512 帧阈值，会将正常的 480 帧回调误判为缓冲不足，触发不必要的分数采样。结合线性插值，在 48 kHz 输入、48 kHz 输出的测试中，16 kHz 正弦波幅度降低约 2.840 dB；44.1 kHz 转 48 kHz 时降低约 3.471 dB。

修复将阈值改为随实际回调长度缩放，并使用预计算的带限插值系数，替代线性插值。保持音频回调不加锁、不分配内存。

## 内部信号测试

通过生产使用的 C 音频桥输入合成信号，在内存中读取处理结果，不播放测试音，不采集或记录通话内容。

| 项目 | 修复后结果 |
| --- | --- |
| 48 kHz → 48 kHz，997 Hz | 幅度误差绝对值小于 0.001 dB |
| 48 kHz → 48 kHz，16 kHz | 幅度误差绝对值小于 0.001 dB |
| 44.1 kHz → 48 kHz，997 Hz | 幅度误差绝对值小于 0.001 dB |
| 44.1 kHz → 48 kHz，16 kHz | 幅度误差绝对值小于 0.001 dB |
| 仅左声道输入时的右声道能量 | 0；未发现内部声道串音 |
| 同采样率随机双声道信号，100% / 50% 音量 | 对齐延迟后，稳态样本误差信噪比约 110.51 dB |
| 同采样率测试中的内部延迟 | 32 个样本，48 kHz 时约 0.667 ms |
| 连续正弦波测试的稳态区间 | 未出现意外的精确零值样本 |

内部延迟不包含系统、设备和蓝牙缓冲。误差信噪比是算法处理结果与合成参考的数值比较，不是扬声器或耳机的物理信噪比。幅度指标仅覆盖上述频点和条件，不是全频段失真测量。

`swift test` 共 8 项通过。新增回归测试覆盖常见回调长度下的高频保真、采样率转换、声道隔离、降采样抗混叠及固定延迟后的稳态样本误差。

## 本机恢复检查

先记录微信和 Chrome 的应用音量及输出选择，再关闭应用控制、退出声之轨，最后重新打开新版并恢复原有控制和音量。

核对结果：默认输出仍为内置扬声器，默认输入仍为内置麦克风，输入和输出采样率均为 48 kHz；系统音量仍为检查前的 62.5%，输出静音关闭。系统音频服务未重启，检查期间没有发现该进程的 Core Audio overload/underrun 日志。

使用设备的持久 UID 比较身份；AudioObjectID 不是跨进程的持久标识，不能单独作为设备是否变化的依据。

## 尚未覆盖

- 没有用测量麦克风或外部回录测量扬声器、耳机的实际频响、失真和端到端延迟。
- 没有把“无过载日志”当作零断音的证明；实时缓冲仍缺少完整的丢帧遥测。
- 没有覆盖所有采样率、声道布局、蓝牙模式、长时间时钟漂移及睡眠唤醒情形。
- 通话音量保护仍依赖未公开的系统属性，兼容性需要随系统与设备更新验证。
